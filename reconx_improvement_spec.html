🎯 Видение продукта

ReconX сейчас — это хорошо собранный набор скриптов с pipeline-оркестрацией. Следующий шаг — превратить его в платформу, где каждый модуль — полноценный плагин с контрактом, а pipeline адаптируется к тому, что нашёл предыдущий шаг.

Ключевое отличие от текущей версии

  • Адаптивный pipeline: нашёл WordPress → автоматически запускает wpscan; нашёл GraphQL → graphql-specific checks; нашёл много JS → углубляет JS mining
  • Evidence-first: каждый finding несёт request/response, скриншот, curl-команду для воспроизведения
  • Confidence scoring: каждый результат получает оценку достоверности, false-positive notes
  • Graph-based asset map: домен → субдомен → IP → порт → URL → технология → CVE — всё связано
  • Plugin API: добавление нового модуля = создание одного файла с определённым контрактом

🚨 Критические дефекты в текущем коде

🔴 CRITICAL — Утечка учётных данных в config.yaml

Токен Telegram-бота (<REDACTED>) и chat_id захардкожены в публичном конфиге. При попадании в git-репозиторий — компрометация бота.

# ПРОБЛЕМА: токен в plain-text в файле, который может уйти в git telegram: bot_token: "<REDACTED_TELEGRAM_BOT_TOKEN>" # РЕШЕНИЕ: только переменные окружения telegram: bot_token: "" # use env TELEGRAM_BOT_TOKEN

Немедленно: инвалидировать токен, создать новый, добавить config.yaml в .gitignore, использовать только TELEGRAM_BOT_TOKEN из env.

🔴 CRITICAL — Race condition в параллельном pipeline

В main.py при параллельном запуске модулей (group=2: portscan + webdetect) используется snapshot = dict(all_results) — поверхностная копия. Вложенные объекты (списки, словари) остаются общими ссылками. При одновременном изменении из двух потоков — data corruption.

# ПРОБЛЕМА snapshot = dict(all_results) # shallow copy! # РЕШЕНИЕ import copy snapshot = copy.deepcopy(all_results)

🟡 HIGH — modules/recon.py: json parsing через недокументированный внутренний API

# recon.py строка ~170 — uses private internal of requests: return requests.models.complexjson.loads(text) # СЛОМАЕТСЯ при обновлении requests # РЕШЕНИЕ import json return json.loads(text)

🟡 HIGH — Отсутствует scope validation

Инструмент не проверяет, не ушёл ли crawling/fuzzing за пределы исходного домена. При редиректах или JS-навигации на third-party домены — сканируются out-of-scope хосты. Нарушение условий bug bounty.

# Добавить в BaseModule: def is_in_scope(self, url: str) -> bool: parsed = urlparse(url) return parsed.hostname.endswith(self.domain) # Фильтровать во всех местах где собираются URL

🟡 HIGH — fuzzer.py: нет global rate limit

rate_limit из конфига используется только в JS Mining. feroxbuster и ffuf имеют собственные rate параметры, но они не синхронизированы. Суммарная нагрузка на цель = ferox_rate + ffuf_rate + katana_concurrency — может быть в 5–10x выше заявленного.

🟡 MEDIUM — ssl_checker.py: синхронные socket calls в параллельном контексте

SSL проверки выполняются синхронно в одном потоке через socket.create_connection с таймаутом 10s на хост. При 60 хостах — до 10 минут только на SSL. Нужна asyncio-версия или ThreadPoolExecutor.

🟡 MEDIUM — html_report.py: XSS через | safe фильтр

В templates/report.html AI-анализ рендерится через {{ ai_analysis | safe }}. Если Ollama/OpenAI вернёт HTML-содержимое со скриптами (промпт-инжекция в LLM) — выполнение JS в контексте отчёта.

# Санитайзировать AI output перед рендерингом: import bleach ai_html = bleach.clean(markdown_output, tags=ALLOWED_TAGS, strip=True)

1. modules/base.py — добавить scope + rate limiting

from urllib.parse import urlparse import threading, time class TokenBucket: """Thread-safe token bucket для глобального rate limiting.""" _instance = None _lock = threading.Lock() def __new__(cls, rate=100): with cls._lock: if not cls._instance: cls._instance = super().__new__(cls) cls._instance.rate = rate cls._instance.tokens = rate cls._instance.last = time.monotonic() return cls._instance def acquire(self, n=1): with self._lock: now = time.monotonic() self.tokens = min(self.rate, self.tokens + (now - self.last) * self.rate) self.last = now if self.tokens >= n: self.tokens -= n return time.sleep((n - self.tokens) / self.rate) # В BaseModule.__init__: self.rate_limiter = TokenBucket(rate=config.get('scan', {}).get('global_rate_limit', 100)) def is_in_scope(self, url: str) -> bool: try: host = urlparse(url).hostname or '' allowed = self.config.get('scope', {}).get('allowed_domains', [self.domain]) excluded = self.config.get('scope', {}).get('excluded', []) return (any(host.endswith(d) for d in allowed) and not any(host.endswith(e) for e in excluded)) except: return False

🔐 Требования к безопасности инструмента

Принципы safe-by-default (обязательно для bug bounty)

  • Scope enforcement: Никакие HTTP-запросы не уходят за пределы разрешённых доменов. Проверка на уровне BaseModule, не только в конфиге.
  • Rate limiting: Глобальный TokenBucket. Максимум scan.global_rate_limit req/s суммарно.
  • No destructive actions: Запрещены DELETE запросы, POST с данными без флага --allow-write, SQL-инжекции в active mode.
  • Audit trail: Каждый HTTP-запрос логируется в audit.jsonl: timestamp, url, method, status, module. Для доказательства соблюдения правил.
  • Reproducibility: Каждый finding имеет curl-команду для воспроизведения. Независимая верификация до репорта.
  • Safe defaults: nuclei запускается только с safe тегами по умолчанию. --enable-risky флаг для опасных шаблонов с подтверждением.

Добавить audit logger

# modules/audit.py class AuditLogger: def log_request(self, module: str, url: str, method: str, status: int, elapsed: float): entry = { 'ts': datetime.utcnow().isoformat() + 'Z', 'module': module, 'url': url, 'method': method, 'status': status, 'elapsed': round(elapsed, 3), } with open(self.path, 'a') as f: f.write(json.dumps(entry) + '\n')

⚠️ Риски и ограничения

Технические риски

  • Ollama/deepseek-r1 на 7B: модель может галлюцинировать уязвимости, которых нет. Всегда указывать confidence и пометку "требует ручной верификации" для AI findings.
  • Nuclei false positives: особенно на info и low severity. Рекомендуется пост-обработка — фильтрация по verified тегу.
  • amass и большие домены: amass может работать часами на крупных организациях. Текущий timeout 180s — разумный, но результаты могут быть неполными.
  • WeasyPrint зависимости: PDF генерация хрупкая из-за нативных зависимостей (pango, cairo). Хорошо что есть Chromium fallback. Рассмотреть puppeteer/playwright как основной PDF engine.

Правовые требования (обязательные)

  • Инструмент использовать только при наличии письменного разрешения (scope definition, rules of engagement)
  • Никогда не запускать против production систем без явного согласования времени
  • Сохранять audit trail всех действий (уже частично реализован через JSON persistence)
  • Добавить --legal-acknowledgment флаг с выводом предупреждения при каждом запуске
